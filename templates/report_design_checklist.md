# Power BI Report Design Checklist

## Page Purpose

- [ ] What business question does this page answer?
- [ ] Who is the audience?
- [ ] What decision should this page support?
- [ ] What action should the viewer take after seeing it?
- [ ] Is this page executive, operational, financial, or analytical?

## Executive Readiness

- [ ] The main message is clear within 10 seconds.
- [ ] The page has an insight-driven title.
- [ ] KPIs include context.
- [ ] Variances are visible.
- [ ] Risks or exceptions stand out.
- [ ] Detail is available through drill-through or tooltip.
- [ ] The page does not require the presenter to explain everything.

## Layout

- [ ] Clear page title.
- [ ] Subtitle or business question included where useful.
- [ ] Last refresh date visible where relevant.
- [ ] KPI row is at the top.
- [ ] Primary visual is visually dominant.
- [ ] Supporting visuals are secondary.
- [ ] Slicers are grouped logically.
- [ ] Detail table is not overpowering the page.
- [ ] Visuals align to a grid.
- [ ] Spacing is consistent.
- [ ] Whitespace is used intentionally.

## Visual Hierarchy

- [ ] Most important information appears first.
- [ ] Page has one clear focal point.
- [ ] Visual sizes reflect importance.
- [ ] Color draws attention to the right items.
- [ ] Less important visuals are visually quieter.
- [ ] The viewer can follow the story from top to bottom or left to right.

## KPI Cards

- [ ] KPI label is clear.
- [ ] Current value is formatted properly.
- [ ] Target or prior period is included where useful.
- [ ] Variance is included where useful.
- [ ] Status is clear.
- [ ] Units are obvious.
- [ ] There are not too many KPI cards.
- [ ] KPI cards are consistent in size and formatting.

## Visual Selection

- [ ] Line charts are used for trends.
- [ ] Bar charts are used for rankings/comparisons.
- [ ] Tables/matrices are used for detail, not as the main dashboard.
- [ ] Scatter plots are used only when relationship/outlier analysis matters.
- [ ] Maps are used only when geography matters.
- [ ] Pie/donut charts are avoided unless simple part-to-whole is needed.
- [ ] Gauges are avoided unless there is a strong reason.
- [ ] Deneb is used only when it materially improves the visual.

## Titles and Labels

- [ ] Page title explains the business message.
- [ ] Visual titles explain the insight, not just the field name.
- [ ] Axis labels are readable.
- [ ] Data labels are not overcrowded.
- [ ] Tooltips provide useful detail.
- [ ] Metric names are business-friendly.

## Color

- [ ] Color palette is restrained.
- [ ] Colors have meaning.
- [ ] Red and green are used only for status/variance.
- [ ] Background does not distract.
- [ ] Contrast is strong enough.
- [ ] Too many category colors are avoided.
- [ ] The page is readable for color-blind users where possible.

## Typography

- [ ] Font sizes are consistent.
- [ ] Page title is largest.
- [ ] Section titles are smaller than page title.
- [ ] Visual titles are readable.
- [ ] Axis labels are legible.
- [ ] No overly decorative fonts.
- [ ] No unnecessary bolding.

## Slicers and Filters

- [ ] Slicers are necessary.
- [ ] Slicers are grouped logically.
- [ ] Default slicer selections are sensible.
- [ ] Slicer labels are clear.
- [ ] Slicers do not dominate the report.
- [ ] Hidden/filter-pane filters are documented if important.
- [ ] Interactions behave as expected.

## Tooltips and Drill-Through

- [ ] Tooltips add useful context.
- [ ] Tooltips do not simply repeat the visual.
- [ ] Drill-through pages exist for detail-heavy analysis.
- [ ] Users can get from summary to detail naturally.
- [ ] Tooltip metrics are clearly formatted.

## Metric Clarity

- [ ] Every major metric has a clear definition.
- [ ] Measures are explicit.
- [ ] Units are clear.
- [ ] Currency is clear.
- [ ] Percentages are formatted correctly.
- [ ] Variances identify actual vs target/prior period.
- [ ] Time period is clear.

## Performance and Usability

- [ ] Page does not have too many visuals.
- [ ] Large tables are limited.
- [ ] High-cardinality visuals are avoided.
- [ ] Too many slicers are avoided.
- [ ] Custom visuals are used carefully.
- [ ] Cross-filter interactions are intentional.
- [ ] Report loads quickly.
- [ ] Bookmarks/buttons are intuitive.

## Accessibility

- [ ] Text is readable.
- [ ] Color is not the only way status is communicated.
- [ ] Contrast is sufficient.
- [ ] Visuals are not too dense.
- [ ] Important values are labeled.
- [ ] Reading order is logical.

## Final Review Questions

1. What is the one thing the viewer should remember?
2. What decision does this page support?
3. Which visual could be removed with no loss of insight?
4. Which metric needs more context?
5. Where is the viewer supposed to look first?
6. Is this page better for an analyst or an executive?
7. What is the highest-impact improvement?
